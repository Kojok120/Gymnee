記録を Slack・Discord にお知らせ

筋トレ部や、ジム仲間のサーバーに。記録を終えたときと、月曜の朝に先週のふりかえりを、選んだチャンネルに流します。仲間の目があると続きます。

つなぎ方

  1. アプリの その他 > 連携 を開き、「Slack に追加」か「Discord に追加」を押します。
  2. Slack・Discord の画面で、ワークスペース（サーバー）とチャンネルを選んで許可します。Discord はそのサーバーで「ウェブフックの管理」ができる人だけが追加できます。
  3. チャンネルに「Gymnee とつながりました」と届けば完了です。

届く内容

記録を終えたとき記録の名前・種目ごとのいちばん良かったセット・セット数・総量・時間・自己ベストの更新・今週の回数と目標
月曜の朝（8 時台）先週の回数と目標・セット数・総量・鍛えた部位・連続達成週・パーティのボスの残り HP と自分の攻撃回数（記録の無かった週は送りません）

どちらを送るかは、送り先ごとにアプリで選べます。メッセージには、仲間を Gymnee に誘うリンクが付きます。

チャンネルにいる全員に見えます。表示名と記録の中身が載るので、送るチャンネルを選んでください。パーティのほかのメンバーの名前と回数は載せません。

やめるとき

  • アプリの その他 > 連携 で送り先を選び、「この送り先を消す」を押します。
  • チャンネルや Webhook を Slack・Discord 側で消した場合は、Gymnee が気づいて自動で止めます。アプリに理由が出ます。

URL を貼って足す（上級者向け）

アプリの「URL を貼って追加」に、次のどれかを貼れます。

Slack の Incoming Webhook

Slack アプリの設定で Incoming Webhooks を有効にし、チャンネルを選んで作った https://hooks.slack.com/services/… の URL。

Discord の Webhook

チャンネルの設定 > 連携サービス > ウェブフック > 新しいウェブフック > 「ウェブフック URL をコピー」で取れる https://discord.com/api/webhooks/… の URL。

自分のサーバー（汎用 Webhook）

https の URL ならどこにでも送れます。Zapier や Make、n8n の Webhook の受け口にも使えます。追加したときに表示される署名の鍵（whsec_…）で、Gymnee から届いたことを確かめられます。

汎用 Webhook の仕様（開発者向け）

Standard Webhooks の形で送ります。本文は JSON で、次のヘッダーが付きます。

webhook-id配信の id。再試行でも同じなので、二重に処理しないための鍵に使えます
webhook-timestamp送った時刻（UNIX 秒）。古すぎるものは捨ててください（5 分が目安）
webhook-signaturev1, + base64(HMAC-SHA256(鍵, "{id}.{timestamp}.{本文}"))。鍵は whsec_ の後ろを base64 で読んだもの

本文の例（記録を終えたとき）

{
  "type": "workout.completed",
  "timestamp": "2026-11-05T10:02:11.000Z",
  "data": {
    "userName": "たろう",
    "inviteUrl": "https://gymnee.app/invite?u=…",
    "workout": {
      "id": "…", "name": "胸と背中", "completedAt": "2026-11-05T10:00:00.000Z",
      "durationMinutes": 45, "exerciseCount": 2, "setCount": 3, "volumeKg": 1100,
      "exercises": [{ "name": "ベンチプレス", "muscle": "胸", "sets": 2, "best": "62.5kg × 8" }]
    },
    "personalRecords": [{ "exercise": "ベンチプレス", "best": "62.5kg × 8" }],
    "week": { "workouts": 2, "goal": 3, "streakWeeks": 1 }
  }
}

type は workout.completed（記録を終えたとき）・weekly.summary（週のふりかえり）・connection.test（追加したときの確かめ）の 3 つです。届くのは、記録を終えてから 2〜3 分後です（アプリが記録を送り終えるのを待つため）。

署名の確かめ方（Node.js）

import { createHmac, timingSafeEqual } from "node:crypto";

function verify(secret, headers, body) {
  const id = headers["webhook-id"], ts = headers["webhook-timestamp"];
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false; // 5 分より古い・未来
  const key = Buffer.from(secret.replace(/^whsec_/, ""), "base64");
  const expected = createHmac("sha256", key).update(`${id}.${ts}.${body}`).digest("base64");
  return headers["webhook-signature"].split(" ").some((s) => {
    const [v, sig] = s.split(",");
    return v === "v1" && sig.length === expected.length && timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
  });
}

body は受け取ったままの文字列で計算してください（JSON を読み直して並べ替えると一致しません）。

署名の確かめ方（Python）

import base64, hashlib, hmac, time

def verify(secret: str, headers: dict, body: str) -> bool:
    msg_id, ts = headers["webhook-id"], headers["webhook-timestamp"]
    if abs(time.time() - int(ts)) > 300:
        return False
    key = base64.b64decode(secret.removeprefix("whsec_"))
    expected = base64.b64encode(hmac.new(key, f"{msg_id}.{ts}.{body}".encode(), hashlib.sha256).digest()).decode()
    return any(hmac.compare_digest(sig.split(",", 1)[1], expected) for sig in headers["webhook-signature"].split())

届かなかったとき

  • 2xx を返せば届いたとみなします。10 秒で打ち切るので、重い処理は受け取ったあとに回してください。
  • 届かなければ 1 分・5 分・30 分・2 時間・6 時間あけて送り直し、6 回で諦めます。429 には Retry-After に従います。
  • 410 を返すと、その送り先を止めます。続けて 5 回諦めた送り先も止めます。止まった送り先は、アプリの「もう一度試す」で戻せます。
  • 転送（3xx）には付いていきません。
